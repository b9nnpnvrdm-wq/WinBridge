# WinBridge technical architecture

Research snapshot, 27 November 2026. Apple Silicon is the primary target. Intel support is a future build and hardware validation track.

## Compatibility stack

| Component | Role and feasibility | Dependencies, licensing and integration |
|---|---|---|
| Wine | Primary Windows API implementation. Start by evaluating a pinned x86-64 Darwin build with new WoW64 under Rosetta, using WineD3D as a first graphics control. Wine 11 supports new WoW64 upstream. A reported Rosetta/WoW64 regression illustrates why build-specific x86 testing matters. | Darwin loader, wineserver, winemac, matching guest modules and build-specific libraries for TLS, fonts, audio and input. Check dynamic library paths and Mach-O slices. Linux NTSync is a Linux kernel path. Wine is LGPL-2.1-or-later. [Wine 11 release](https://list.winehq.org/hyperkitty/list/wine-releases@list.winehq.org/message/UL6L2GJ55VYUJ5KUMBZ3TZSXRFJ52QG6/) · [License](https://github.com/wine-mirror/wine/blob/master/LICENSE) · [Darwin build candidate](https://github.com/Gcenx/macOS_Wine_builds) · [WoW64 bug report](https://list.winehq.org/hyperkitty/list/wine-bugs@list.winehq.org/thread/FQ2G55RFO6OZMTLHY66TDCNIH2VZKH6X/) |
| Rosetta 2 | System translation for the x86-64 macOS Wine process. Wine provides Windows API and WoW64 machinery. Apple documents AVX and AVX2 in its current translation environment and excludes AVX-512. Probe actual OS and guest behavior. | Apple system component. Apple lists general-purpose availability through macOS 27 with narrower functionality afterward. Develop a native engine track in parallel and avoid depending on undocumented future availability. [Apple translation environment](https://developer.apple.com/documentation/apple-silicon/about-the-rosetta-translation-environment) |
| DXVK | D3D9/10/11 over Vulkan, with D3D8 also available upstream. Compare pinned upstream and Darwin-adapted builds. | Zlib. Meson, MinGW-w64 and shader tooling for upstream cross-builds. Requires matching guest DLLs, Wine Vulkan and a compatible host ICD. Requirements vary by release, including robustness and maintenance extensions. An advertised Vulkan version alone is insufficient. Test DXGI presentation, shader stutter, and unsupported formats. [Upstream](https://github.com/doitsujin/dxvk) · [Vulkan requirements](https://github.com/doitsujin/dxvk/wiki/Driver-support) · [Darwin fork history](https://github.com/Gcenx/DXVK-macOS/releases) |
| VKD3D-Proton | D3D12 over Vulkan. Treat as experimental until a pinned stack passes feature checks and workloads. Evaluate WineHQ VKD3D as a separate baseline if useful. | LGPL-2.1 family. Meson, glslang and MinGW-w64 for cross-builds. Upstream documents Vulkan 1.3, substantial update-after-bind descriptor limits and required extensions. Check compatible DXGI, resource barriers, queues and synchronization. [Requirements and build](https://github.com/HansKristian-Work/vkd3d-proton/blob/master/README.md) · [License](https://github.com/HansKristian-Work/vkd3d-proton/blob/master/COPYING) |
| MoltenVK | Vulkan portability implementation over Metal, with SPIR-V-to-Metal shader translation. Evaluate as a compatibility option where appropriate. Khronos reports community maintenance and recommends KosmicKrisp on Apple Silicon. | Apache-2.0. Requires Metal, correct loader/ICD discovery and portability enumeration when using the standard loader. Verify surface creation and device capabilities from the actual Wine process. Pipeline compilation and API workarounds can affect frame times. [Project](https://github.com/KhronosGroup/MoltenVK) · [Runtime guide](https://github.com/KhronosGroup/MoltenVK/blob/main/Docs/MoltenVK_Runtime_UserGuide.md) |
| KosmicKrisp | Mesa Vulkan-on-Metal driver for Apple Silicon on macOS 26+, with Vulkan 1.4 conformance reported by LunarG. Compare with MoltenVK. | Mesa has per-file licensing, predominantly MIT. Requires Metal 4 and a matching loader/ICD ABI. Verify the particular distribution’s Mach-O slices before considering it for Rosetta Wine. Check exact DXVK and VKD3D-Proton feature profiles independently. [Mesa driver](https://docs.mesa3d.org/drivers/kosmickrisp.html) · [LunarG status](https://www.lunarg.com/the-state-of-vulkan-on-apple-oct-2026/) · [Mesa licensing](https://docs.mesa3d.org/license.html) |
| DXMT | Direct-to-Metal D3D10/11 candidate for the first gaming benchmark. | Metal 3 and specific winemac APIs. Check patch compatibility and guest architecture for each build. Upstream labels v0.80 the last MIT release and announces a move to LGPL. Verify the chosen tag’s terms. [Runtime requirements](https://github.com/3Shain/dxmt/wiki/Device-System-Runtime-Specifications) · [Releases](https://github.com/3Shain/dxmt/releases) |
| GPTK and D3DMetal | Apple’s evaluation environment provides an optional comparison lane for eligible use. | Apple terms apply to its proprietary components. Keep out of the distribution unless the exact terms affirmatively allow the intended use and distribution. [Apple Game Porting Toolkit](https://developer.apple.com/games/game-porting-toolkit/) |
| FEX and Proton | Investigate native Darwin Wine/FEX forks for x86 translation and use Valve Proton as an upstream reference for patch selection and test practices. | Upstream FEX targets ARM64 Linux and uses a Linux userspace for its Linux execution path. Valve Proton targets Linux Steam. Darwin ports need independent maintenance, testing, and per-component license review. [FEX](https://github.com/FEX-Emu/FEX) · [Experimental Darwin Wine/FEX](https://github.com/Irz-Z/wine-macos-native) · [Valve Proton](https://github.com/ValveSoftware/Proton) · [Proton notices](https://github.com/ValveSoftware/Proton/blob/proton_11.0/dist.LICENSE) |

Before selecting a backend, check Windows DLL architecture, loader and ICD architecture, available instance/device extensions, features, descriptor limits and WSI under the exact engine build. Enable a backend only after device creation and known-output rendering succeed. Benchmark the same scene and settings with cold and warm caches. Record CPU/GPU frame times, median and tail frame times, shader stalls, memory pressure and rendering errors.

## Guest architecture policy

| Guest | Apple Silicon execution candidate | Initial state |
|---|---|---|
| x86-64 | x86-64 Darwin Wine under Rosetta. Native Darwin Wine plus a tested translator is the longer-term candidate. | PE header detected. Runtime unverified. |
| x86 | New WoW64 inside the selected engine. Validate a 32-bit installer, child process startup and graphics independently. | PE header detected. Runtime unverified. |
| ARM64 | Native Darwin Wine requires compatible guest ABI, exception handling, thread state and memory behavior. Test real programs with 4 KB assumptions on 16 KB hosts. Evaluate ARM64EC and ARM64X separately. | PE machine detected. Hybrid load configuration and runtime unverified. |
| ARM32 | Requires a Windows ARM32 guest execution path and Wine support. Evaluate user-mode emulation plus thunking if a viable upstream path exists. | PE header detected. Execution deferred. |

The PE machine field is a routing hint. Final ARM64EC and ARM64X images can advertise a conventional machine ID with hybrid metadata elsewhere. EXE bootstrapper and child architectures may differ. MSI is a compound document, so installation planning must inspect installer metadata and validate custom actions against the engine. [PE format](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format) · [ARM64EC image identification](https://learn.microsoft.com/en-us/windows/arm/arm64ec)

## Module contracts

| Module | Responsibilities |
|---|---|
| Core Engine | Own a versioned runtime catalog keyed by digest and host slice. Probe capabilities per OS and runtime. Pin the engine per prefix. Apply dependency recipes with hashes and licenses. Launch using argument vectors, explicit working directories and per-child environment. Report exit status, cancellation and redacted diagnostics. |
| Application Manager | Create or choose a prefix, run an EXE directly or an MSI via Wine’s `msiexec`, and record confirmed launch targets. Run registered uninstallers with the owning runtime and preserve shared prefixes and saves. Reconcile cancelled or interrupted installs and retain diagnostics. |
| Gaming Engine | Select a validated WineD3D, Vulkan or Metal profile per title. Own per-game overrides, cache keys, controller mapping, fullscreen and display settings, and performance capture. Restrict shader cache invalidation to the affected title and runtime/backend/driver combination. |
| Storage Manager | Keep catalog and operation state in local Application Support. Store immutable runtimes, mutable prefixes, game data and disposable caches in distinct roots. Support user-selected and external SSD roots after validating identity, permissions and filesystem semantics. Report allocated storage by category, handle an offline volume as unavailable, and resume or roll back interrupted transfers. |
| SwiftUI | Show installed apps and games, installation progress, engine settings and troubleshooting. Call typed services rather than assembling process commands. Store macOS bookmark data where needed for user-selected locations and test access after relaunch or remount. |

The install flow persists operation state before creating or mutating a prefix. Serialize prefix mutations and retain a recoverable state on failure. New prefixes are isolated from one another for configuration and installed files. A Wine prefix does not form a security boundary for untrusted applications. Keep runtime dependency installation explicit and preserve access controls of the launching user. Do not copy or redistribute proprietary Microsoft Windows components. Publish upstream notices, corresponding source and patch provenance as applicable before distributing runtime builds.

## Platform boundary

Linux can exercise PE and MSI metadata handling, process and manifest contracts, state transitions, cache keys, redaction, and storage fault simulation. Linux Wine integration can later provide a control for fixtures if provisioned. It cannot certify Darwin Wine or Apple GPU behavior.

Apple Silicon macOS with Xcode must validate Mach-O loading, signing and notarization, Rosetta and native Wine engines, Metal/Vulkan drivers, windowing, fullscreen, controllers, audio, external-volume behavior and SwiftUI. Use real Apple hardware for graphics, latency and compatibility qualification. The release target is a native Swift/Xcode app, with a Foundation-only service layer where practical. Python currently provides dependency-free developer tooling and a behavioral reference.
